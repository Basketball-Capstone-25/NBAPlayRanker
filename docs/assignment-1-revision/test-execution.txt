Failures and next steps

Shot data: BST-138/139 -> SCRUM-538
The dataset has 18,746 self-opponent rows out of 1,332,515. All 7,520 game groups
with at least 100 shots have only one shooting-team label. A fresh TOR export
had 51 self-opponent rows in 5,000 rows. Two synthetic ETL checks also failed.
Rebuild from authoritative raw events and rerun the checks. The original raw
source is missing, so the cause of every bad row is not confirmed. The separate
Synergy play-type dataset is not implicated by these checks.

Gameplan first Build: BST-140 -> SCRUM-539
The same Q4, down-five, 28-second prompt gave different rankings on the first
and second builds. Build from the newly parsed context, including focus weight.

Gameplan flags: BST-141 -> SCRUM-540
The screen recognizes need-three and switching, but the request code omits
those flags. Pass them to ranking and test the result. This finding uses the
screen and source code; the outgoing request was not captured.

Overtime: BST-142 -> SCRUM-541
The parser returns period 5 for "Overtime, down 2 with 1:00 left.", but the
Gameplan quarter control and summary show Q4. Keep overtime in the display
and request, then rerun the full flow.

Analyst shot pages: BST-143/144 -> SCRUM-544
Shot Plan and Shot Heatmap return 403 for an analyst. Align page and API
permissions, then test allowed and denied roles.

Model Metrics: BST-145 -> SCRUM-542
Holdout results load, but the pipeline summary stays Loading and Refreshing
stays disabled. Give each request its own state and handle both success and
error. This run did not capture duplicate network requests.

Shot Statistical Analysis: BST-147 -> SCRUM-545
The page crashes with a TypeError reading length after data loads. Match the
response adapter to the page and test empty and populated responses.

Shot Model Metrics: BST-146 -> SCRUM-543 (Verify)
The default request timed out after 300 seconds on October 6. It was not rerun
here. Serve saved metrics instead of training during a page request, then
retest. The earlier result is in tests/historical/.

To rerun locally

Use the pinned Python dependencies and Node lockfile. Restore the shot dataset
if needed, then run from the repository root:

  backend/.venv/bin/python -m pytest backend/tests scripts/test_verify_elaboration_live.py -q
  backend/.venv/bin/python -m pytest backend/tests/test_shot_attribution_regression.py --runxfail -q
  npx vitest run
  npx tsc --noEmit --incremental false

The second command should fail until SCRUM-538 is fixed. Review the xfail
markers when fixing it. Live checks need private test accounts; credentials
are not included. Rerun each failed case after its fix and keep its suite in
progress until the required cases pass.
