Current failures and planned fixes

BST-138 / BST-139 -> SCRUM-538: shot-team attribution.
The retained dataset has 18,746 self-opponent rows out of 1,332,515. All 7,520
game groups with at least 100 shots have only one shooting-team label. A fresh
5,000-row TOR export contains 51 self-opponent rows. Two synthetic ETL checks
also fail. Repair from authoritative raw events, rebuild derived data and rerun
the checks. The historical raw source is unavailable, so the synthetic ETL
defect does not prove the cause of every corrupted retained row. Synergy
play-type rankings are a separate dataset.

BST-140 -> SCRUM-539: the first Gameplan Build uses old context.
The same Q4, down-five, 28-second prompt produced different ranking values on
the first and second builds. The first request captures earlier state, including
the focus weight. Build from the newly parsed context snapshot and verify that
the first and repeated builds use the same inputs.

BST-141 -> SCRUM-540: Gameplan drops parsed qualitative flags.
The screen recognizes need-three and switching flags, but the current request
construction omits them. This result combines browser state with source review;
it is not a new network-payload capture. Forward and validate the flags, then
test their effect at the ranking boundary.

BST-142 -> SCRUM-541: overtime becomes quarter four in Gameplan.
For "Overtime, down 2 with 1:00 left.", the live parser returns period 5 and the
screen reports an overtime warning, but the quarter control and summary show
Q4. The check stops at that mismatch. Preserve the overtime period through
display and request construction, then rerun the whole flow.

BST-143 / BST-144 -> SCRUM-544: analyst shot pages call coach-only APIs.
Shot Plan and Shot Heatmap return 403 from an analyst session. Align the page
and endpoint permissions, then verify the allowed role and rejected roles.

BST-145 -> SCRUM-542: Model Metrics does not finish its loading state.
Holdout results appear while the pipeline summary remains Loading and the
Refreshing button stays disabled. Separate request states and confirm that
success and error paths both return the page to a usable state. The fresh
evidence does not claim a duplicate-request network trace.

BST-147 -> SCRUM-545: Shot Statistical Analysis crashes after loading data.
The current browser shows a client exception; its console reports a TypeError
reading length. Align the response adapter and UI schema, then verify empty
and populated responses render without an exception.

BST-146 -> SCRUM-543 remains Verify. The expensive default Shot Model Metrics
request timed out after 300 seconds in the October 6 audit. It was not repeated
in this revision. The historical evidence is kept in tests/historical, and the
planned fix remains linked. This is not counted as a newly executed failure.

How to review and rerun

Open BST-137 at https://basketball-strategy.atlassian.net/browse/BST-137 and
follow each case's feature or fix link. The case descriptions contain the
specific steps. tests/coverage.json records the 18 current campaign results;
tests/legacy-coverage.json maps the 52 legacy cases to exact test names.
tests/jira-verification.json records the final readback and preserved owners.
tests/jira-project-status.json records the full live project counts and issue
statuses. tests/additional-jira-verification.json covers the added legacy
results and suite rollups; browser-and-suite-verification.json records the other
fifteen scoped checks.
Personal local path prefixes in three shareable logs were replaced by
<project> and <evidence>; evidence-normalization.json records their source and
published hashes. Test results, inputs, assertion names and times are unchanged.

From the repository root, use the pinned Python development dependencies and
Node lockfile, restore the shot dataset if needed, then run:

  backend/.venv/bin/python -m pytest backend/tests scripts/test_verify_elaboration_live.py -q
  backend/.venv/bin/python -m pytest backend/tests/test_shot_attribution_regression.py --runxfail -q
  npx vitest run
  npx tsc --noEmit --incremental false

The second command is expected to fail until SCRUM-538 is fixed. The strict
xfail markers make an unexpected pass visible, so the markers must be reviewed
when the fix lands. Authenticated live tests require the private test accounts;
their credentials are excluded from the repository and evidence.

Retest each failed case after its linked fix. Keep the suite in progress until
the required cases pass. Passing isolated unit, API and database checks does
not clear the browser failures or validate every application feature.
